# Correct historical records and preserve issued reports

Extend the workbook with an append-only `RecordCorrections` ledger. Its first five headers are `Revision`, `Target Record`, `Action`, `Field`, `Replacement`. Revisions are positive integers in ascending order. The stable key for an entry in an input ledger is `SheetName:RowNumber` using its immutable original row. The input ledgers are append-only during correction and replay. Support keys for `EmploymentPeriods`, `DepartmentTransfers`, `TemporaryAssignments`, `DepartmentChanges`, and `PayrollCosts`. `Action` is `Replace` or `Void`. For `Replace`, `Field` matches the target ledger header and `Replacement` is the typed new Excel value. Later replacements of a field supersede earlier ones. A voided record stays void. The source record itself stays intact. Blank rows have no effect. Expose a status in column F: `APPLIED` or `INVALID_TARGET`. Continue admitting previous M1–M6 inputs when no corrections are present.

The effective view uses corrected records throughout existing lookup, reporting, payroll and approval behavior. A movement invalidated by its corrected employment history or department code is removed from results and listed as needing review. Reports recalculated for a prior month use those corrected facts. Issued reports and approvals preserve their contents as of issuance. A newly submitted request uses the corrected state and any applicable issued approval. Flag an existing issued approval that is no longer feasible for review while retaining its stored decision. Create a visible `MovementReview` table. In columns A and B list record keys and `REVIEW` for the affected movements. Use `Request:<Request ID>` as the key for an issued request. The valid test inputs preserve the date order of surviving ledger rows and do not include conflicting successors or periods. A base history or approved movement that has not been corrected stays readable.

For the publication workflow, add a visible `IssuedRecords` sheet with columns `Publication ID`, `Metric`, `Value`. The evaluation harness publishes the actual workbook output by copying approved reports and decisions to this ledger as values. It then appends corrections to the same workbook copy. The metric for an issued decision is `Decision:<Request ID>` and for its reason is `Reason:<Request ID>`. Each issued request occurs once in the ledger. Add a visible `IssuedPublicationQuery` sheet with inputs `A2` (publication ID) and `B2` (metric) and output `C2` (published value). A query of an issued result must read the stored value for that publication and metric, while the ordinary report selectors continue to show the corrected result. An unknown key returns blank. Keep the existing live reports and ledgers intact and return a recalculating XLSX.
