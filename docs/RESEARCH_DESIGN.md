# 研究设计

## 任务演进

OBM-036 和医疗、赛事原型研究反事实真值生成及跨文件更新。酒店公式工作流增加了可重算的业务逻辑、跨文件发布和旧功能复测。有状态酒店进一步让程序执行多步操作并把结果写回同一份 Excel。

## 对照与评分

- **独立模式**每个里程碑从标准前序文件开始。
- **连续模式**继承上次实际提交。当前有状态运行器继续继承业务检查失败的可读文件，前序文件不可用时记录中断。早期公式运行器在失败时可回退，所以每次都读取真实起点字段。
- **新功能验证**对本轮新用例比较修改前、后状态，分别计数失败变通过、原本已通过、继续失败和缺少结果。**旧功能验证**对前轮用例计数通过保持、通过变失败、遗留失败和缺少结果。
- **依赖验证**除了查看公式和代码，还会阻断前序状态并观察下游。有状态版本移除实际持久化的释放记录，再尝试递补。

现有公式实验的 10 项结果列包含中间计算。有状态实验的操作数按命令接口统计。Navidrome 报告按其官方 F2P、N2P、P2P 定义，双边的测试粒度各自保留。

酒店报告中的 `new.fail_to_pass` 给出新检查由失败变为通过的数量。 `retained.pass_to_pass` 和 `retained.pass_to_fail` 分别给出旧检查的保持和回归数量。

## 证据归档

公开目录提供运行摘要、变更概况、测试计数、诊断与清单。私有档案保存实际输入、提交、逐项评分、轨迹、测试、Oracle 和参考文件。每个 run 使用独立标识。重算得到的修改前评分标记为事后补测，原始评分和复核同时保存。

公开源码含用于复现实验的原型样例和规则。正式留出的任务数据和逐项评测答案需要继续单独管理。
