## 论文指标与数据访问

Table 2 的 Precision 同时取决于新增测试通过数 `N_fixed` 和旧测试失败数 `N_broken`，公式为 `(N_fixed + 1) / (N_fixed + N_broken + 1)`。论文 §5.5 以 Claude Code 和 Claude Opus 4.6 为例，统计旧测试失败在不同轮次的产生、传播、未执行和修复。继承与无法执行的事件在后期占比上升。论文未给出「至少发生一次真实新增回归的里程碑数 / 升级数」。平均每轮 17.1 项新增测试和 6,218 项旧测试是全基准的覆盖统计。[论文 §5.1](https://arxiv.org/html/2603.13428v4#S5.SS1) · [论文 §5.5](https://arxiv.org/html/2603.13428v4#S5.SS5)

## 本地 Navidrome 原始评分重计

- **新增要求。** 原始评分有六轮未达到全部新增要求，两轮有明确的测试失败记录。`003_sub-02` 修复重复迁移后，在同一份 Agent 提交上复测为 83/95，新增测试有 10 项失败和 2 项异常。跨库匹配与访问相关测试存在行为偏差。清理相关的模拟组件异常仍需业务复核。
- **新回归的候选。** `003_sub-04` 的四条旧用户编辑测试均在 `LibrarySelectionField` 的模拟组件加载失败，业务断言没有执行。已有受控浏览器复测中，早期 `001` 与最终 `004` 提交都能编辑并保存用户，刷新后能读到改动。浏览器证据覆盖这条操作路径。`007` 另有两条原始旧测试由通过变为失败，官方过滤将其排除。报错是找不到播放列表移除控件的测试文本，实际操作未独立复核。
- **继承失败。** `004` 的 56 条旧测试在紧邻上一轮已经失败。`003_sub-02` 的修正复测还显示一条旧测试在 `003_sub-01` 就已失败。统计单位是测试结果变化。多条失败可能共享根因。
- **缺失与环境。** 五轮原始评分缺少至少一条计分结果。重复迁移问题已经通过同提交复测定位。其他缺失涉及编译错误、套件缺失等情形，原因需要逐项复核。

## 与 Lite 38 的比较

Lite 38 的 **1/12** 对应两条轨迹各六次升级，只计确认为业务回归的轮次。M7 轨迹二改变了月初、年初的入职日计数边界，四个旧案例里九条检查由通过变为失败。恢复原边界后，两个代表案例的五条诊断检查均恢复。Navidrome 本地这次运行暂未确认新的业务回归，若干轮覆盖不全。两个本地试验的测试覆盖、任务和推理档位也不同。当前数据无法判断 Lite 38 的回归发生频率是否偏低。[M2 双轨结果](../lite38_temporary_assignment_m2/analysis.md) · [M7 双轨结果](../lite38_evolution_m7/analysis.md)

正式比较应同时报告可比较的连续升级数、旧测试执行覆盖及至少一项真实新增回归的升级数。逐轮归档新增未通过、旧功能回归、继承失败、缺失或评测异常。同一轮允许多个标记。对两个连续快照使用相同业务断言，排查测试变动与环境差异。
