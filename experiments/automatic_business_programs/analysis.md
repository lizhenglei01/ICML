# Level 3 与 Level 4 的关联、分组和排名构建

### 算子对应关系

| 已核查的源码 | 原有做法 | Office 构建器采用的做法 |
|---|---|---|
| KoPL `Program/executor_rule.py` 中的 `Relate`、`QueryAttr` | 按关系及方向遍历已知实体，或读取实体属性 | `JOIN`、`LOOKUP` 用业务主键关联表。右表主键必须唯一，每条左表记录都须匹配。没有照搬知识图谱的遍历接口。 |
| HiTab `qa/nsm/execution/executor.py` 中的 `filter_tree`、`filter_level`、`aggregate`、`rank` | 先选定层级表格的行列范围，再汇总或排名 | `GROUP_BY` 由业务字段形成组，`GROUP_SUM`、`GROUP_AVG` 只汇总组内记录。`RANK` 保留行及稳定键。 |
| Logic2Text `execution/APIs.py` 中的 `APIs`、`argmax`、`nth_argmax` | 为表格操作登记参数类型、返回类型和执行函数，并取指定名次的行 | 每个算子登记输入、参数、返回类型、约束和执行函数。用 `RANK`、`TOP_K` 取一段排名，用 `ARGMAX` 取第一名。 |

参考仓库以浅层、按需读取的方式克隆到 `三方依赖代码/`。三份执行器已检出，源码版本见清单。本项目独立实现算子，执行时无需导入三个参考仓库。

### 从输入到资产

向生成模型提供采购主题、业务目标、算子契约和 Level 3／4 的结构要求。模型提出表及字段、采样范围、政策图和报告目标。六个对象、三个分组和每对象三条记录是当前试验规模。模型使用的指标、门槛、分组名称、排名方向及前几名来自提案。两个提案由 GPT‑6.2‑sol 各在一个独立临时会话中生成，会话工具被禁用。

编译器验证操作的输入输出类型、主键、参数、单位保留、环路以及结果是否实际依赖关联和分组。Level 4 额外要求排名截点下游能够到达报告。构图支持多个集合接入 AND／OR，也允许嵌套组合。两个实际提案由模型选择了较简单的条件结构。旧模式继续接受已归档任务的原结构。

程序生成记录，逐条尝试更正一个数值。Level 3 须使至少一个未改自身数据的对象改变资格。Level 4 须实际改变排名截点，且至少两名其他对象改变资格。Level 3 在均匀采样下首次未找到合格事件，后来采用均匀与分组采样交替搜索。两次搜索均使用同一份生成提案，失败记录保留。

Excel 保存履约记录及旧资格，PPT 保存供应商分组名录及旧资格图，Word 保存政策和旧汇总。程序从实际渲染的 Office 文件读回资料，将题面许可的更正带入计算，复核前后结果。SQLite 通过独立的表连接、分组和查询执行路径，逐节点复算。每道题生成原生参考文件、依赖图、前后 GT、证据位置和可执行 Oracle。

| 验证项目 | Level 3 | Level 4 |
|---|---:|---:|
| 已登记规则下的推导层数 | 8 | 10 |
| 已登记规则下完整推导所需文件 | 3 | 3 |
| 更正后资格变化且自身数据未变的对象 | 1 | 3 |
| 独立复算一致的节点次数 | 16 | 20 |
| 参考提交必改对象 | 9/9 | 10/10 |

两组参考提交通过。每组的未修改、漏改 Word、错值、破坏受保护公式、篡改图表缓存五类提交均被拒。12份原生文件通过 LibreOffice 重新打开和导出检查。三个文件的充分性依据实际读回和已登记推导规则，不涵盖对旧报表的所有可能捷径。两题分别生成，适合核查结构实现。被测 Agent 测试尚未开始，难度层级只是候选定义。

### 复现入口

使用项目已有的 Worldloom 环境。在未安装 Worldloom 的工作站，可从本地检出的 `synthetic-foundry/src` 加入 Python 路径。

```bash
PYTHONPATH="$PWD/三方依赖代码/synthetic-foundry/src" \
python -m multifile_reconstruction.reasoning_graph_mvp.logic_first.scenario_bench \
  --topic '供应商采购管理' --goal '按全局分组排名复核供应商季度资格' \
  --program-level 4 --effort low --out artifacts/new_program_task
```

对已经归档的提案可用 `--reuse` 重放，重放时保持原主题、目标和随机种子。本轮先验收 Level 3／4。DocHop 的17条图表规则继续由原图表任务使用，优化和动态调度留待后续验证。
