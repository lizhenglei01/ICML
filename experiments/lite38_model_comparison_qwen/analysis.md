# Lite 38 Qwen3.5-27B 对照

本次使用与 GPT‑6.2‑sol 干净复跑相同的原始员工工作簿、M1 题面、隐藏输入、GT 和冻结评分器。模型通过隔离的 Codex 工作空间读取和编辑文件。M2 的输入是千问实际提交的 M1 文件，SHA‑256 与 M1 已归档提交一致。[运行清单](manifest.json) · [GPT‑6.2‑sol M1 基线](../lite38_generic_transfer_clean_m1/analysis.md)

| 里程碑 | 实测结果 |
|---|---|
| M1 可复用永久调动 | 冻结评分 21/45，旧功能 21/21，本轮新增检查 0/24 |
| M2 临时借调 | 免费额度用尽，无提交、无分数 |
| M3–M7 | 未执行 |

M1 的失败可以直接从提交工作簿复核。题面要求 `DepartmentTransfers` 的前四列依次为员工 ID、生效日期、原部门和目标部门。提交将流水号放在 A 列、员工 ID 放在 B 列、生效日期放在 C 列，在第 5 行写表头。冻结测试沿规定接口注入多次调动后，员工查询、月度和年度部门人数未正确更新。原有入离职统计、HR 成本和合同提醒的保护检查均通过。

M2 的 Responses 流返回 `Free quota exhausted`，虽有 HTTP 200，这次试验没有产出 M2 工作簿。新提供的百炼北京工作空间支持 `qwen4-max`，对 `qwen3.5-27b` 返回 `403 PERMISSION_DENIED`。Qwen4-Max 从相同原始工作簿独立开始，后续只继承自己的交付物。

这条轨迹提供一个在相同 M1 条件下可以复核的新增功能失败。M2 中断之后，没有该模型的旧功能回归观测。
