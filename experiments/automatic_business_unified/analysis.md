# 统一业务对象与依赖图构建

统一入口使用 `--program-level 1` 至 `4`。提出业务对象、基础指标及引用关系属于原来的基础观测阶段，具体行在图验证后才生成。模型在四个独立临时会话中依次提出基础观测、正向图、反向路径和合成政策。反向请求只给基础观测、目标定义和输出列类型，省略正向节点和公式。程序使用一个算子注册表编译运算、关联、分组、排名和逻辑；算术沿用现有量纲规则。旧的双表提案可以按照归档请求重放。

## 一个实测采购案例

输入是「供应商采购管理」「复核季度资格」和 Level 4。没有在请求中给出表清单、关联字段名、业务评分公式或门槛。生成模型自行提出三个对象集合和两条外键。模型还决定按订单金额计算供应商的加权质量评分，比较品类得分，复核资格并汇总人数与订单金额。构建程序接受一到四个对象集合，最多四十行，支持明确声明的单列主键和无环外键。本轮现场调用只验收一个案例。

| 对象路径 | 模型声明的连接 |
|---|---|
| 到货验收批次 → 采购订单 | `batch_order_id` → `order_id` |
| 采购订单 → 供应商 | `order_supplier_id` → `supplier_id` |

关联时检查字段所属的键域以及右侧主键唯一性。两侧字段名称可以不同。程序按模型声明的取值范围和引用关系生成记录。正向模型在同一张图中组合 `JOIN`、`LOOKUP`、分组统计、`MUL` 和 `DIV`。政策阶段自主选择排名前两品类及85分的供应商门槛，其最终输出包括名单、人数和入选供应商的参评订单金额合计。

反向模型重建了目标计算，使用了不同的中间列名和乘法参数顺序。输出键、列和单位一致，在20批合成输入上复算一致。当前实现把这记为抽样一致，将原始反向提案留档，实际执行采用正向编译结果。合成口径经过结构和数值验证，样本验证不覆盖行业标准或所有合法输入。

## 更正与评分

程序找到一条更改验收分数的事件。只改一个源单元格，改变排名截点，使另一个自身记录保持原样的供应商退出。名单改变，人数仍为1，订单金额汇总传播更新。正式资产布局由程序搜索选出。较小的供应商名录放在 PPT，订单和验收记录放在 Excel，政策在 Word。基于实际读回和登记规则的完整推导深度是18层，使用三份文件。该数值描述已登记的计算路径。

独立 SQLite 路径复算更正前后共40个节点。参考提交的9项必改、350项保护和119项语义检查全部通过。原文件不改、漏改 Word、填错更正值、改坏保护公式和破坏图表缓存的五类错误提交均被拒。三份初始文件和三份参考文件都能重新打开并导出。重复构建对照的依赖图和 GT 一致。结果来自一个合成案例，尚无被测 Agent 成绩。

第一次用原提案编译时，旧的标签校验拒绝了节点名称中的中文逗号。节点说明改用通用安全文本校验，名单成员及标识仍遵守原约束。随后用原始四份提案重放完成，初次拒绝记录也归档。
