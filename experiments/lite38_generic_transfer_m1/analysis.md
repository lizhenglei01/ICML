# Lite 38：通用部门调动功能（GPT-6.2-sol）

## 任务与实现载体

本轮要求模型修改原始 Lite 38 工作簿，使调动表和 Excel 公式成为可重复运行的业务功能。没有要求提交独立 Python 程序。模型提交了一个修改后的 XLSX，报告创建 250 条记录的调动表，并让员工查询、当前部门汇总、月度和年度人数统计读取调动记录。

评测将隐藏调动输入写入提交工作簿、用 LibreOffice 重算，再将结果与独立状态 Oracle 预先计算的 GT 比较；另外对照原始工作簿复测入离职统计、成本、合同提醒和起始部门字段。参考工作簿只用于证明任务可实现及评分器有效，不参与候选评分。

## 结果

修正后的诊断评分为 **44/45**：

| 隐藏案例类别 | 结果 |
|---|---:|
| 多员工、多次调动及跨月统计 | 15/15 |
| 离职员工调动 | 14/15 |
| 200 条调动记录容量 | 15/15 |
| 合计 | **44/45** |

旧功能保护项 **21/21 通过**。唯一失败属于新功能：对离职员工登记调动时，候选工作簿的调动行状态显示“Check employee ID or hire date”，没有接受其稳定档案 ID，导致该员工在月初人数中仍留在原部门。参考工作簿在同一评分器和输入下通过 45/45，因此这不是评分器无法处理该记录的普遍问题。

这说明本次工作簿已能处理普通在职员工的多次调动和 200 行输入，但对已离职员工的历史档案引用仍有缺口。它尚未实现题目范围内完全通用的调动功能。

## 评分器修正记录

首轮评分 v1 不作为正式结果：它错误地把年度辅助表按月度日期比较，并把月度期初解释为报告开始日前一天。检查提交公式后发现，工作簿的年度辅助表由年份选择器驱动；题目规定调动在生效日当天起作用。因此修正后，v2 将年份选择器设为案例对应年份，并按报告显示的期初日期计算。v1 原始 JSON 保留在私有档案中，未覆盖。

需要注意：v2 的修正发生在模型运行之后，故 44/45 是**事后纠正评分设置后的诊断重算**，不是严格的预注册盲测结果。若要作为正式能力结论，应在冻结 v2 套件后做一次干净复跑。
