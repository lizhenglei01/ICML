# 酒店与采购端到端自动构建

同一个入口分别接受「酒店经营分析／季度经营资格复核」和「供应商采购资格评估／季度供应商采购资格复核」。每个主题生成一个业务案例和四种证据布局。流程复用了既有的公式语义登记、量纲运算、证据搜索、Worldloom 渲染和原生文件 Oracle。

## 构建方法

1. GPT-6-astra 在四次独立会话中分别提出基础观测及其范围、正向派生指标、从候选目标出发的反向路径、合成资格政策及汇总。正式输入仅由主题和目标提供领域信息。四阶段通过结构化结果传参，反向请求省略了目标公式。
2. 程序检查符号表达式、量纲、类型、范围、引用和环路。已登记概念用来源登记表对照。合成指标使用可执行的运算定义和约束，例如分子属于总量的比例。模型政策经编译后先冻结。独立逐行解释器与向量依赖图分别计算事实、筛选对象和统计结果。
3. 按政策分支采样基础数据，枚举候选账本更正。过滤没有产生预期传播的候选，为可用事件选择两种可证深度及两种文件跨度。对缺少足够证据的每个文件子集，检查能改变答案且保持其可见证据、旧报告和任务事件相同的合法反例。
4. 用统一的节点类型选择候选载体。按真实 Office 对象定位、读回、编译评分规则和修改参考文件。校验 Word 段落、Excel 单元格和公式、PPT 原生可编辑图表、缓存和内嵌工作簿。

## 结果

| 主题 | 浅层最短深度 | 深层最短深度 | 集中版最少文件数 | 分散版最少文件数 |
|---|---:|---:|---:|---:|
| 酒店经营资格 | 3 | 5 | 1 | 3 |
| 供应商采购资格 | 3 | 4 | 1 | 3 |

两个案例各有一条通过验证的反向路径，分别重新发现了正向探索采用的计算关系。八套参考提交均通过。每套的未修改提交、漏改 Word、错误数值、破坏保护公式以及篡改图表缓存均被拒绝。初始与参考 Office 文件共 48 份，均在独立 LibreOffice 配置下打开并成功导出 PDF。构建过程中出现过模型标识符长度限制和 PPT 容量配置错误，修正后以原始提案重放。

四种布局是静态修订任务的对照。最短深度按已登记的算子、路径和集合短路计算。两组采用合成指标及资格政策，程序验证的是给定观察口径下的运算和一致性。任意行业客观定义仍需要可信登记，代码会拒绝未经确认的标准概念。本轮两组验证各只有一个案例，因此尚无跨行业覆盖率或单位构建成本估计。评测期间只使用生成模型，保留了独立线程审计。

## 复现入口

```bash
python -m multifile_reconstruction.reasoning_graph_mvp.logic_first.scenario_bench \
  --topic '酒店经营分析' --goal '季度经营资格复核' \
  --out artifacts/automatic_business_demo/hotel

python -m multifile_reconstruction.reasoning_graph_mvp.logic_first.scenario_bench \
  --topic '供应商采购资格评估' --goal '季度供应商采购资格复核' \
  --out artifacts/automatic_business_demo/procurement
```

模型鉴权沿用项目的 Codex 推理通道。离线重放使用相同主题、目标和已归档的 `proposals` 子目录，并增加 `--reuse`。本地私有归档保存原始请求、调用审计、业务图、节点前后值、候选拒绝统计、Office 产物、证据地图与 Oracle。公开仓库保留代码、验证统计和校验摘要。
